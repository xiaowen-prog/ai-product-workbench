# 原有代码保留与分阶段实施清单

更新时间 2026-11-20

## 当前判断

当前本地工程里有两套后端职责。

- `dist/` 是用户确认的 v29 正式视觉入口，应该保留。
- 当前 `backend/app/` 是为了让 v29 先跑通而写的简化项目状态适配器，能保留其中的同源静态服务、错误返回、状态恢复和预览门禁，但不能继续作为老师开发项目的核心后端。
- 老师第二个项目「自主 Agent 工作台」是后端开发维护源。它的任务、事件、Todo、工具权限、知识注入、后台 Job、AgentRun、暂停恢复、SQLite 持久化、真实模型 adapter、Swagger/OpenAPI 路由和测试必须保留。
- 老师第一个项目 `agent-workshop` 的 `blueprint/`、需求事实六维度、固定规则选型、方案自检、审稿、PRD 版本和 handoff 必须作为需求澄清与方案输入层接入。

## 分阶段优先级

### 阶段 0 已完成

- 备份当前 `backend/` 到 `backups/backend-before-teacher-dev-20261120-175702/`
- 将老师第二个项目的后端、脚本、阶段文档快照保存到 `.local/teacher-dev/idea-to-launch-kit-source/`
- 保留现有 v29 前端备份和当前工作区改动

### 阶段 1 当前实施

- 把老师第二个项目后端作为本地正式后端维护源
- 保留原有 `/api/v1/tasks` 等 Swagger/OpenAPI 路由与 schema
- 接入老师第一个项目的需求事实、问题、PRD、方案、审稿和 handoff 服务
- 用一个融合项目 ID 关联需求澄清产物与后端开发任务

### 阶段 2

- 让 v29 页面接入融合 API
- 需求澄清按后端返回的问题逐轮展示
- 选项支持直接点击，推荐选项和自由输入保留
- 未完成需求事实、PRD 确认、方案审稿和用户验收时，不出现后端开发入口

### 阶段 3

- 将确认后的 handoff 写入老师开发项目的任务 brief 和 artifact
- 通过老师原有 Task、Job、AgentRun、事件流和测试链路执行后端 MVP
- 保留暂停、恢复、重试、权限确认和失败状态

### 阶段 4

- 本地真实模型链路验证
- `node --check dist/app.js`
- 老师后端测试与融合链路测试
- Swagger/OpenAPI 路由回读
- 1280、390、320 宽度检查

## 不会提前删除的内容

- 当前旧后端和旧数据在备份目录中保留，直到融合链路完成一次本地验收。
- 老师原有开发后端的路由、schema、权限和测试不因前端接入而改名或删除。
- `docs/review/` 只作为历史证据，不会重新变成正式入口。

## 当前阻断点

正式融合前需要把第一项目的产物映射到第二项目的 Task、Artifact 和 AgentRun。这个映射属于后端接入，不属于视觉重做。实现时会先保留第二项目原路由，再新增融合路由，完成回读和测试后再让 v29 页面切换过去。
